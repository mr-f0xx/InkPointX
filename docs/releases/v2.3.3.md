## InkPoint X v2.3.3

Addresses slow or apparently unresponsive navigation reported on XTEINK X3.

- The UC8279 display driver now waits for a delayed BUSY signal and treats
  failed refreshes as failed. It no longer commits an incomplete frame as the
  next refresh baseline, so navigation can retry cleanly.
- X3 cold starts remain awake and interactive. Only a genuine wake from deep
  sleep requires the Power button to stay held.
- A held wake Power button no longer blocks navigation or housekeeping; only
  that wake press and its release are filtered.
- The recovery button chord is checked after every reset source.
- Firmware metadata now reports the exact installed version to the UI and OTA
  updater.

Stable universal ESP32-C3 firmware for XTEINK X3 and X4. Update through
**Settings → System → Check for updates**. If navigation is too slow to reach
the updater, copy `update.bin` to the root of a FAT32 microSD card, power off,
then hold **left side / Up** while powering on.

`firmware.bin`, `update.bin` and all X3/X4-labelled images contain the same
firmware; checksums are in `SHA256SUMS`.

Validation: all 196 host tests, production-driver delay/failure simulations,
static analysis, localization checks and the production OTA size gate. No
physical X3 was available for final testing, so validation on both X3 panel
revisions is still requested. The X4 dark-mode behavior from v2.3.2 is
unchanged.
