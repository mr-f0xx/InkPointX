## InkPoint X v2.2.26

This release completes support for newly manufactured XTEINK X3 units whose UC8279D display controller has blank MTP waveform storage.

- Replaces the legacy OTP-dependent UC8279 path with the complete current CrossPoint X3 display driver.
- Programs the panel power rails, booster, PLL, VCOM/data interval, 792 × 528 partial window, and related controller registers explicitly.
- Supplies external full, fast, and grayscale waveform tables instead of assuming they are present in factory MTP.
- Preserves the validated blank-MTP detection introduced in 2.2.25, including rejection of floating-bus false positives.
- Synchronizes both image planes during full refresh and uses the CrossPoint partial-window path for fast refreshes.
- Keeps the established UC8253 X3 and both X4 display paths unchanged.
- Adds a host regression test that verifies the critical CrossPoint initialization commands and LUT banks remain present.

Version 2.2.25 could identify the revised controller correctly but its older driver still expected factory-programmed waveforms. The firmware could therefore boot while the e-ink panel continued showing the retained `Update complete` image from recovery. Version 2.2.26 fixes the first visible application frame as well as subsequent full and partial refreshes.

For stock X3 recovery, copy `update.bin` to the root of a FAT32 microSD card. From the CrossPoint/Witch Hunt recovery file picker, select `firmware.bin`. Both files contain the same application image and do not overwrite the bootloader, partition table, NVS, or SD recovery mechanism. An SD-recovery installation does not provide an automatic application rollback guarantee; if the new application does not display, force a restart by holding Power for 10–15 seconds and use the existing recovery mechanism to reinstall the last working image.
